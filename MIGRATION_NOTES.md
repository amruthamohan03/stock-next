# Migration Notes — PHP → Next.js + PostgreSQL

This document tracks how the original PHP app maps onto the new stack and what
is / isn't ported in this first "foundation + core modules" pass.

## Database

- **All 35 tables** from the MariaDB dump are defined in `src/db/schema.ts`
  with identical table and column names, so the original data loads unchanged
  via `scripts/mysql-to-pg.mjs`.
- Type mapping: `int` → `integer`, `bigint` → `bigint`, `enum('Y','N')` →
  `varchar` (values preserved), `tinyint(1)` → `integer` (0/1), `decimal` →
  `numeric`, `datetime/timestamp` → `timestamp`.
- `AUTO_INCREMENT` primary keys → `GENERATED BY DEFAULT AS IDENTITY` so explicit
  ids from the dump load cleanly; the converter appends `setval()` calls to move
  each sequence past the loaded max id.
- Foreign keys are **not** enforced at the DB level (the original mostly used
  MyISAM without real FKs); relationships are resolved in queries.
- The `vw_stock_ledger` MySQL view is reproduced as the `/stock` page query
  (Drizzle joins) rather than a DB view.
- `licenses_t` and `locals_t` come from an unrelated customs/import-export app
  that shared this database. They're kept in the schema for a lossless data
  import but are **not** surfaced in the UI.

## Auth & sessions

| PHP                                   | Next.js                                   |
| ------------------------------------- | ----------------------------------------- |
| `SessionManager` + `$_SESSION`        | JWT cookie (`jose`) in `src/lib/session.ts` |
| `password_hash` / `password_verify`   | `bcryptjs`; `$2y$` hashes normalized to `$2b$` |
| CSRF token per form                   | SameSite=Lax cookie + server actions      |
| `AuthController::login`               | `loginAction` server action               |

Existing passwords keep working — the bcrypt hashes are compatible.

## RBAC

- `role_menu_mapping_t` drives the sidebar and permissions, exactly like the PHP
  `MenuModel` / role-menu mapping.
- Menu hierarchy is built from `menu_level` (0 = top) and `menu_id` (parent),
  matching `MenuModel::getMenu()`.
- **Super Admin (role_id = 1)** sees every active menu, as before.

## The generic CRUD pattern

New masters can be added quickly:

1. Add the table to `src/db/schema.ts` (already done for every table).
2. Register a whitelist in `src/lib/masters-config.ts`.
3. Create `src/app/(dashboard)/<name>/page.tsx` that fetches rows + any lookup
   options and renders `<CrudTable apiKey="<name>" … />`.

The generic route `src/app/api/masters/[key]/route.ts` handles create/update/
delete with per-master field whitelisting, audit columns, and soft-delete when a
`display` column exists.

## Deliberate differences from the original

- **Soft delete** for masters (sets `display = 'N'`) instead of hard delete, so
  history is preserved. Lists filter on `display = 'Y'`.
- Server-rendered pages + a small REST layer instead of AJAX-populated PHP views.
- Tailwind/shadcn UI instead of the Bootstrap/Tabler theme (a visual rebuild,
  not a pixel match).
